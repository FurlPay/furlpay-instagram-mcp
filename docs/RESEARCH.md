# Official Meta API research

Verified on **2026-09-27**, with conversation references checked on **2026-09-28**, directly against Meta's developer documentation before implementing the corresponding Instagram tools. This is an implementation research record, not a promise that every capability listed here is exposed by this release. The tool registry and `INSTAGRAM_API.md` describe the implemented subset.

## Product and version decision

Use **Instagram API with Facebook Login**, the current configuration of the Instagram Graph API, for this release. It supports Instagram professional Business and Creator accounts linked to a Facebook Page. Personal/consumer Instagram accounts are outside this API's scope. Publishing Stories is restricted to Business accounts. [Official product description](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login)

Use the explicitly versioned `https://graph.facebook.com/v26.0` host. Meta's Graph API versions table lists **v26.0, released July 29, 2026**, as the newest release on the research date. Several Instagram reference pages still say v25.0 in their examples and “latest” labels; the central versions table takes precedence. [Version table](https://developers.facebook.com/docs/graph-api/changelog/versions), [v26 changelog](https://developers.facebook.com/docs/graph-api/changelog/version26.0)

The alternative **Instagram API with Instagram Login** supports professional accounts without a linked Facebook Page and uses `graph.instagram.com`. It has its own `instagram_business_*` permissions and token exchange/refresh flow. It now supports insights and mentions; it is inaccurate to describe all of these as unavailable. Its feature coverage differs from Facebook Login, especially hashtag search, ads, and media deletion. This release does not mix tokens or scope names between configurations. [Platform comparison](https://developers.facebook.com/documentation/instagram-platform/overview), [Instagram Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login)

## Verified endpoints and permissions

All paths below are relative to the versioned Graph host. `IG_ID` always means the connected account selected through OAuth, never an account ID supplied arbitrarily by an agent. The basic Facebook Login read permission set is `instagram_basic` and `pages_read_engagement`. Discovery of eligible Pages additionally requires `pages_show_list`. Business Manager role assignments may require `ads_read` or `ads_management`; individual reference pages have inconsistent wording about whether one or both is required, so deployment must validate its actual role arrangement during App Review.

## Fields, ownership, and pagination

The account reference documents `id`, `username`, `name`, `biography`, `profile_picture_url`, `followers_count`, `follows_count`, `media_count`, and `website`. It does **not** document `account_type`; do not invent this value or infer Business versus Creator from the Facebook Page's `instagram_business_account` relationship. [Account fields](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user)

Media may provide `id`, `caption`, `media_type`, `media_product_type`, `media_url`, `permalink`, `timestamp`, and other requested fields. Missing counts and copyright-restricted media URLs remain missing. `owner` is returned as `{id}` when the querying app user owns the media. Validate `owner.id` against the connected account; reject missing or mismatching ownership. Comment `media.id` allows a separate ownership lookup before mutation. [Media fields](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media), [Comment fields](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-comment)

Read one bounded page. Never follow returned URLs blindly: they can contain tokens. Carry cursors as opaque strings, retaining the original tool/query parameters. Tagged-media pagination returns cursors without `next` links. Hashtag recent-media uses a maximum page size of 50, only returns media from the past 24 hours, excludes usernames, and may return the **same** `after` cursor across pages. Do not assume unchanged cursor means completion. [Tags pagination](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/tags), [Recent hashtag media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag/recent-media)

## Publishing decisions

Images use publicly reachable JPEG URLs. Reels use video URLs and `media_type=REELS`; a generic standalone video tool must disclose that it publishes a Reel. The old standalone `media_type=VIDEO` publishing option was removed in 2023. Video carousel children still use the documented carousel child flow. A carousel contains at most ten child containers; wait for video children before creating/publishing the parent. [Publishing changelog](https://developers.facebook.com/documentation/instagram-platform/changelog), [Container parameters](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media)

Containers expire after 24 hours, with a documented creation ceiling of 400 per rolling 24 hours. Poll `status_code`: `IN_PROGRESS`, `FINISHED`, `ERROR`, `EXPIRED`, or `PUBLISHED`. Meta recommends polling at one-minute intervals for up to five minutes. Only publish `FINISHED`; persist the workflow and do not blindly retry ambiguous POST outcomes. The publishing guide currently gives conflicting 100-versus-50 daily quotas in different sections, so read the quota endpoint and respect API errors. [Publishing guide](https://developers.facebook.com/documentation/instagram-platform/content-publishing), [Container reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-container)

Story publishing requires a Business account; the returned profile does not establish that type. Treat an operator's Business-account declaration as deployment configuration, never as an API-derived profile field. Meta remains authoritative on eligibility. AI-generated media may use the official `is_ai_generated` flag; on carousels it belongs only on the parent container. [Product restriction](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login), [AI-content parameters](https://developers.facebook.com/documentation/instagram-platform/content-publishing#ai-content)

## Analytics capability map

Media insights are lifetime metrics. Request only metrics compatible with the returned media product type; carousel children have no independent insights. Empty results mean unavailable data, not zero. Counts can lag by up to 48 hours. Story insights expire after 24 hours and low-viewer stories can return permission-style errors. [Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights)

| Product | Verified metrics relevant to this connector |
| --- | --- |
| FEED | `comments`, `follows`, `likes`, `profile_activity`, `profile_visits`, `reach`, `reposts`, `saved`, `shares`, `total_interactions`, `views` |
| REELS | `comments`, `likes`, `reach`, `reposts`, `saved`, `shares`, `total_interactions`, `views`, `ig_reels_avg_watch_time`, `ig_reels_video_view_total_time`, `reels_skip_rate` |
| STORY | `follows`, `link_clicks`, `navigation`, `profile_activity`, `profile_visits`, `reach`, `replies`, `reposts`, `shares`, `total_interactions`, `views` |

Facebook Login additionally supports aggregated `total_comments` and `total_likes` on Feed/Reels, and `total_views` on all three surfaces. `facebook_views` requires appropriate crossposted content; `crossposted_views` applies to Reels. Supported breakdowns are `profile_activity` → `action_type` and `navigation` → `story_navigation_action_type`. Mixing incompatible breakdowns causes errors. [Metric compatibility](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights)

Account interaction metrics use `period=day&metric_type=total_value`: `accounts_engaged`, `comments`, `follows_and_unfollows`, `likes`, `profile_links_taps`, `reach`, `replies`, `reposts`, `saves`, `shares`, `total_interactions`, and `views`. `reach` also permits `time_series`. Demographic metrics require different lifetime/timeframe rules and minimum audience thresholds. `followers_count` is a profile total, not an invented account-insights metric. Account `impressions` is deprecated; use `views`. [Account Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights)

## Webhooks and messaging

For Facebook Login, subscribe the **Facebook Page** using `POST /PAGE_ID/subscribed_apps` with a Page token. Configure Instagram object fields in the App Dashboard. Comment/mention notifications require `instagram_manage_comments`; story insights require `instagram_manage_insights`; Page plumbing requires `pages_manage_metadata`, `pages_read_engagement`, and `pages_show_list`. Supported fields include `comments`, `live_comments`, `mentions`, `story_insights`, and the documented Messenger event fields. There is no general “media changes” subscription in the reviewed matrix. [Field/permission matrix](https://developers.facebook.com/documentation/instagram-platform/webhooks/fields)

Validate the GET verify token and return the exact challenge. Validate POST `X-Hub-Signature-256` using HMAC-SHA256 over raw request bytes and the app secret before parsing or storing data. Store events durably, deduplicate, and bind entries to connected accounts. [Webhook setup](https://developers.facebook.com/documentation/instagram-platform/webhooks/setup)

Facebook Login messaging uses Messenger Platform: `GET /PAGE_ID/conversations?platform=instagram`, `GET /CONVERSATION_ID?fields=messages`, and `GET /MESSAGE_ID?fields=id,created_time,from,to,message,reply_to`. Conversation/message IDs are opaque strings. Only the newest 20 messages support detailed retrieval. Permissions include `instagram_basic`, `instagram_manage_messages`, and `pages_manage_metadata`; use a Page token. [Conversations API](https://developers.facebook.com/documentation/business-messaging/messenger-platform/conversations)

The direct `GET /CONVERSATION_ID/messages` edge is also officially documented. Its reference requires `pages_messaging` in addition to `instagram_manage_messages`; this differs from the Instagram-specific Page-conversations guide, which does not list `pages_messaging`. Request the stricter permissions if using the direct edge. The conversation's `participants` field explicitly includes the connected Instagram account ID or Page ID as well as the other participant's scoped ID, allowing account-binding checks. Do not confuse conversation-routing `is_owner` (which app owns a reply thread) with ownership by the connected account. [Messages edge](https://developers.facebook.com/docs/graph-api/reference/conversation/messages), [Conversation fields](https://developers.facebook.com/docs/graph-api/reference/conversation)

Sending text uses `POST /PAGE_ID/messages`, `recipient:{id:IGSID}`, `message:{text:...}`, with the Page token and `instagram_manage_messages`. Text must fit 1,000 UTF-8 bytes. A recipient must first contact the business; automation has a 24-hour response window and must provide human escalation. Agent-supplied timestamps are not proof of an open window. The HUMAN_AGENT extension is not a permission for automated AI messages outside that window. [Send API](https://developers.facebook.com/documentation/business-messaging/instagram-messaging/features/send-message), [Messaging overview](https://developers.facebook.com/documentation/business-messaging/instagram-messaging/overview), [Human escalation](https://developers.facebook.com/documentation/business-messaging/instagram-messaging/features/human-agent-escalation)

## Authentication and rate limits

Facebook Login establishes authorization for the linked Page/account. Use server-side code exchange and token inspection; maintain actual token/data-access expirations and granted permissions. The separate Instagram Login flow exchanges a short-lived token for a long-lived token, then permits refreshing an unexpired token at least 24 hours old for another 60 days. Do not apply that Instagram refresh endpoint to Facebook tokens. [Facebook access tokens](https://developers.facebook.com/documentation/facebook-login/guides/access-tokens), [Instagram token lifecycle](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/business-login)

Instagram account operations generally use Business Use Case limits; Hashtag Search and Business Discovery use Platform limits. Usage is not a universal fixed requests-per-hour allowance. Read usage headers, respect throttling, bound concurrency, and retry only safe reads with exponential backoff. Meta documents separate messaging limits, including two conversations calls per second per Instagram professional account. [Platform rate limits](https://developers.facebook.com/documentation/instagram-platform/overview#rate-limiting)

## Removed capabilities and misleading legacy assumptions

The historical Instagram API is not the current authorization model. Arbitrary personal-account search, following/follower lists, relationship mutations, public popular-media feeds, location/geography media discovery, and liked-media feeds have no verified counterpart in this product. Mark those requests `unsupported_by_current_instagram_api`; do not scrape them.

Instagram Basic Display stopped serving requests on December 4, 2024. Old Instagram Login `business_*` scopes were replaced by `instagram_business_*` scopes in January 2025. Deprecated insights include account impressions, `video_views`, and old profile-contact time series. However, do not overstate removals: media deletion and restricted like/unlike APIs have since been introduced officially. [Instagram changelog](https://developers.facebook.com/documentation/instagram-platform/changelog)

## Documentation inconsistencies handled explicitly

- Version examples lag the official Graph API release table; use v26.0.
- The comment moderation guide omits top-level creation, but the exact media-comments reference explicitly supports it.
- Publishing token tables mention Page tokens while endpoint references mention User tokens; use endpoint-specific requirements and retain both server-side after authorization.
- Publishing rate numbers conflict; query the authoritative quota endpoint.
- The deletion reference has an erroneous POST syntax example despite DELETE headings and DELETE cURL examples; implement DELETE.
- Instagram Login's media reference labels some familiar fields Facebook-only; avoid assuming field parity across products.
- Metric reference examples retain deprecated demographics timeframes; obey current metric-specific restrictions rather than copying examples.
- Messenger's direct conversation/messages references additionally require `pages_messaging`, while the Instagram-specific conversation guide lists only Instagram permissions plus Page metadata; use the stricter direct-edge permission set when calling that edge.

No live Instagram account was used to override these official-documentation findings. Production access still requires the appropriate Meta app configuration, review, account roles, permissions, and real-account acceptance testing.
